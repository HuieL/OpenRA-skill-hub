# Selected document → edit → new result

## Establish the target

Keep the selected project, original input identities, available revisions and
execution machine with the request. Obtain selected bytes through the
application's documented read or materialization mechanism. A remote process
cannot read a Mac path merely because that string appears in a reply.

Prefer the already installed and approved component. Installation, selection,
enabling, execution and granting access are separate decisions. Choosing Craft
Suite does not install or start every component. Use only capabilities and
formats documented by the actual installed tool and permitted by the current
application. Do not invent version-dependent host fields or API endpoints.

## Perform one explicit change

Edit a working copy, not the canonical original. Record both exported output
and editable-source identities before changing them. An unreadable or missing
catalog entry does not prove that no source exists. Ask for the missing source
or state the limitation instead of silently replacing it with an export.

Choose a bounded edit and identify the intended layer, shape, page or text
object. Photo internal commands are not necessarily separate MCP tools.
Authorization of an outer batch tool does not authorize every nested operation.
Check the requested changes and file access against the current tool's policy.
Do not assume the connection options of one component work for another.

Capture the actual operation result and output observations. A timeout,
disconnect or partial batch may leave edits on disk or in an open document.
Stop dependent actions and reconcile the current state. Do not replay writes,
retry under a new identity or invent a new revision to conceal uncertainty.

## Photo → Vector

Export the selected Photo result and preserve its editable source separately.
Check the exact image bytes, dimensions and hash before passing them to Vector.
Import that selected result through the approved Vector tool, then preserve
both the Vector source and its export. A bitmap embedded in SVG remains raster
content; do not describe it as newly editable vector geometry.

Keep this relationship: original Photo input → selected Photo export → Vector
import → Vector source/export. Relate observations to those same bytes, not
equal filenames or independently green reports. Verify relevant geometry, text,
fonts, clipping and requested changes. Static source inspection cannot prove
actual rendering, reopening or native editability.

## Human continuation and return

For a verified live connection, use the same managed working document and
execution machine. Two programs opening one filename do not share unsaved
in-memory changes. If only external editing is available, describe it as
external. Ask the human to save and resolve conflicting edits before reading
returned bytes. A launch button is not proof that the source opened or saved.

A handoff note may identify files and revisions, but it is not their content,
credentials, permission or proof of a previous operation's outcome. Importing
or reading that note does not restore a process, finish a save or authorize a
write. Download cancellation does not mean a file was saved.

Validate the returned source and export against the currently selected inputs
before asking the application's existing result workflow to create a new
revision. Preserve lineage and the original hash. If one part saved and another
failed, report partial completion and keep both observations. A fresh file
hash alone does not prove an earlier operation finished.

For Deck, preserve editable slides, notes and fonts. For Print, edit only a
derived PDF without overwriting its authoring source. A visual redaction must
not be represented as secure content removal without further checks.

Finish with the exact changes, input/output identities, tool version, checks,
remaining uncertainty and next authorized step. Use only a revision actually
confirmed by the application; never manufacture one from a file hash.
